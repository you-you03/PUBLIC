# 要件定義書

## 1. 背景・目的

* 背景：スクリーンショット画像に対して、赤枠・矢印・テキスト等の注釈を素早く追加し共有したい。
* 目的：Chrome拡張として「撮影→編集→PNG保存」までを一気通貫で提供し、注釈付きスクショ作成の手間を削減する。

## 2. システム化の範囲

### 対象

* Google Chrome（Manifest V3）拡張機能
* 対象画面：**Chromeタブ（表示中の可視範囲）**
* 追加：**可視範囲内での範囲指定（切り抜き）**

### 対象外（本ドキュメントの前提）

* OS標準スクリーンショット操作（PrintScreen等）をトリガーにした自動起動
* ページ全体キャプチャ／スクロール合成
* クラウド保存／チーム共有機能

## 3. 機能要件

### 3.1 キャプチャ機能

* F-001：可視範囲キャプチャ

  * 操作：拡張アイコン／ショートカット／右クリックメニュー（いずれか、または複数）
  * 結果：表示中タブの可視範囲を画像化し、編集画面へ遷移
* F-002：範囲指定キャプチャ（可視範囲内）

  * 操作：範囲選択モード開始→ドラッグで矩形選択→確定
  * 結果：可視範囲キャプチャ画像から指定領域を切り抜き、編集画面へ遷移

### 3.2 編集機能（注釈）

* F-010：オブジェクト追加

  * 矩形（枠線のみ）
  * 楕円（枠線のみ）
  * 正円（楕円作成時にShift等で縦横固定）
  * 矢印（線＋矢印ヘッド、枠線扱い）
  * テキスト
* F-011：スタイル変更

  * 線色（図形・矢印）
  * 線幅（図形・矢印）
  * テキスト色
  * テキストサイズ
* F-012：編集操作

  * 選択／移動
  * リサイズ（ハンドル）
  * 削除
  * Undo / Redo
* F-013：編集補助（MVP優先度低）

  * ズーム（100/200等）
  * ガイド・スナップ（将来）

### 3.3 保存機能

* F-020：PNG書き出し

  * 形式：PNG固定
  * 保存先：Downloads直下
  * 命名：`YYYYMMDD_HHMMSS.png`
  * 例：`20251219_143501.png`

## 4. 非機能要件

* NFR-001：性能

  * 可視範囲キャプチャ→編集画面表示まで体感遅延を最小化（目安：数秒以内）
  * Undo/Redoや移動・リサイズがカクつかないこと（一般的PCを想定）
* NFR-002：互換性

  * Chrome最新版近傍（個人利用想定のため厳密な下位互換は緩め）
* NFR-003：セキュリティ・プライバシー

  * 画像・注釈データはローカルで完結（外部送信なし）
  * 必要最小限の権限のみ付与
* NFR-004：保守性

  * Editor（UI）とキャプチャ（背景）を分離し、責務を明確化

## 5. 前提条件・制約条件

* Manifest V3（Service Worker）前提
* 範囲指定は「可視範囲内の切り抜き」に限定
* 図形は枠線のみ（塗りつぶし無し）
* 個人利用（ストア公開・審査対応は必須スコープ外）

# 主要定義書

## 1. 用語定義

* 可視範囲：現在タブで画面に表示されている領域
* 範囲指定：可視範囲上でユーザーがドラッグして選ぶ矩形領域
* Editor：注釈を編集する拡張機能の編集画面（extension page）
* 注釈オブジェクト：図形・矢印・テキスト等の編集対象要素

## 2. システム全体概要

* 拡張機能は「キャプチャ → Editorで注釈 → PNG保存」を提供する。
* 範囲指定時は、content scriptでオーバーレイ選択UIを表示し、選択座標を用いてキャプチャ画像をトリミングしてEditorへ渡す。

## 3. 主要機能一覧

* キャプチャ（可視範囲）
* 範囲指定（可視範囲内）
* 注釈編集（矩形／楕円・正円／矢印／テキスト）
* スタイル設定（線色・線幅、文字色・サイズ）
* Undo/Redo
* PNG保存（Downloads直下、指定命名）

## 4. データ・外部連携の概要

* 外部連携：なし（クラウド・API送信なし）
* データ：

  * 背景画像：キャプチャ結果（dataURL/Blob）
  * 注釈：Editor内で保持するオブジェクト配列（将来拡張でJSON永続化可能）
* ブラウザAPI利用：

  * `tabs` / `activeTab`（キャプチャ対象タブ）
  * `downloads`（保存）
  * `scripting`（範囲指定UI注入）
  * `commands`（ショートカット）
  * `contextMenus`（任意）

# 実装計画書

## 1. 開発方針

* 段階開発（MVP→範囲指定→UX改善）
* Editorの注釈操作は実装工数・品質の観点から **Canvasライブラリ採用**を基本方針（Fabric.js or Konva.js等）
* 画像データは当面「Editorタブ内で完結」（永続化は後回し）

## 2. 体制・役割（個人開発想定）

* 企画・要件：本人
* 実装：本人
* テスト：本人（主要ブラウザ環境・解像度での動作確認）

## 3. スケジュール案（目安の工程分割）

* Phase 0：プロトタイプ設計

  * manifest/権限/画面遷移/データ受け渡し方式の確定
* Phase 1：MVP（可視範囲キャプチャ＋Editor＋PNG保存）

  * キャプチャ→Editor起動
  * 注釈（矩形/楕円/矢印/テキスト）、色・線幅・文字サイズ
  * Undo/Redo、保存命名
* Phase 2：範囲指定（可視範囲内）

  * オーバーレイUI（ドラッグ選択）
  * devicePixelRatio考慮のトリミング実装
* Phase 3：品質・UX

  * ショートカット整備、右クリックメニュー、ズーム、初期値保存（任意）

## 4. リスクと対応方針

* R-001：範囲指定の座標ズレ（DPI差異）

  * 対応：CSS px → device px変換（`devicePixelRatio`）を仕様化しテスト観点に含める
* R-002：MV3 Service Workerの制約で処理が分散し複雑化

  * 対応：キャプチャ・起動はSW、編集・合成はEditorに責務分離
* R-003：編集操作の自前実装が重い

  * 対応：ライブラリ採用（選択・変形・テキスト編集の成熟度を優先）
* R-004：権限過多で運用しづらい

  * 対応：最小権限化（範囲指定を使うときだけ注入等）

# 設計書

## 1. システム構成図（文章ベース）

* ユーザー操作
  →（拡張アイコン/ショートカット/メニュー）
  → Service Worker（背景）
  → （必要時）Content Script（範囲指定UI）
  → Editor（編集画面）
  → Canvas合成
  → Downloads保存

## 2. 機能構成

### 2.1 キャプチャ起動

* 起動手段

  * Toolbarボタン
  * commands（ショートカット）
  * contextMenus（任意）

### 2.2 範囲指定モード（可視範囲内）

* Content Scriptが行うこと

  * 全画面オーバーレイ表示
  * ドラッグ開始点・終了点を取得（CSS px）
  * ESCでキャンセル、Enter/MouseUpで確定
* Service Workerが行うこと

  * 可視範囲キャプチャ実行
  * 選択座標に基づきEditorへ「トリミング指示＋画像」を引き渡し
* Editorが行うこと

  * 受け取った画像をCanvasに描画
  * 必要ならEditor側でトリミング（実装都合で選択）

### 2.3 注釈編集（Editor）

* オブジェクト種別

  * Rect：x,y,w,h, strokeColor, strokeWidth
  * Ellipse：x,y,rx,ry, strokeColor, strokeWidth（Shiftでrx=ry）
  * Arrow：x1,y1,x2,y2, strokeColor, strokeWidth, headSize
  * Text：x,y,text, fontSize, color
* 共通操作

  * 選択、ドラッグ移動、リサイズ（矢印は端点移動）
  * 削除
  * Undo/Redo（操作履歴スタック）

## 3. データ設計概要

* Editor内部状態（例）

  * `backgroundImage: { dataUrl | blobUrl, width, height }`
  * `objects: AnnotationObject[]`
  * `history: { undoStack, redoStack }`
  * `defaults: { strokeColor, strokeWidth, fontSize, textColor }`（任意でstorage保存）

## 4. 画面・API設計方針

### 4.1 画面（Editor）方針

* 左ツール：選択 / 矩形 / 楕円 / 矢印 / テキスト
* 右設定：線色・線幅、文字色・文字サイズ
* 上部：Undo/Redo、保存（PNG）
* 図形は枠線のみ（塗り無し）

### 4.2 内部API（メッセージング）方針

* Service Worker → Editor

  * `OPEN_EDITOR`：背景画像（dataURL/Blob参照）、トリミング情報（任意）
* Content Script → Service Worker

  * `REGION_SELECTED`：{x,y,width,height, dpr}
  * `CANCEL_REGION`：キャンセル通知
* Editor → Service Worker（または直接downloads）

  * `EXPORT_PNG`：Blob生成後の保存要求（downloads権限の扱いにより）

## 5. 仕様上の重要ポイント（範囲指定）

* 座標変換仕様（必須）

  * 選択座標（CSS px）を `devicePixelRatio` 倍して画像ピクセルに変換してからトリミングする
* 初期スコープ

  * 「可視範囲内」のみ（スクロール合成なし）
